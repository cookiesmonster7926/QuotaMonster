5 · 選了什麼 · 拒絕了什麼

選擇

  1. 主角是問題本身。19pt 那一行是 session 真正問出口的句子（要我繼續嗎？ / 可以執行 rm -rf .build 嗎？），不是「usage 正在等待輸入」這種第三人稱轉述。專案名退到第二行，app 名稱一個字都沒有。
  2. 身分不靠名字，靠三件事。(a) 窗口對齊在選單列圖示正下方，帶一個 8pt 尖角指回去；(b) 左上角那顆圖示就是選單列上那顆本人 —— 同一份 GlyphGeometry（r=7.25 環 + x=7.6/10.2/12.8 的三個 chevron）、同一個 #FF9E0A、同一個只有警示狀態才有的呼吸；(c) 第二行是使用者自己的 cwd，一個冒充的視窗不會知道 ~/Antigravity/usage。
  3. 環上的段數 = 等待數。1 不切、2 切兩段、4 切四段，直接沿用 alertSegments(blocked:)。選單列與窗口在同一瞬間說同一個數字，這是「這兩個是同一個東西」最便宜的證據。
  4. 琥珀只有一個意思。#FF9E0A 取自 GlyphRenderer.alert (1.00, 0.62, 0.04)。額度色階（藍 → 綠 → 紅）在這個窗口裡一次也沒出現 —— 這裡跟額度無關。琥珀只落在四個地方：左緣 3pt、圖示、等待秒數、主按鈕。
  5. 等待時間是唯一跳色的文字。「等了 2m 14s」——「等了」不跳，數字跳，mono tabular，讀秒時不會抖。
  6. 三種情況同一套骨架，只是後段降級。窗口能給幾句全文就給幾句，給不完的只列名字：1 → 問題獨佔；2 → 兩句全文；≥3 → 一句全文 + 其餘一行。英雄行永遠只有一個。
  7. ≥3 的摘要仍然帶著一個具體的問題。只寫「4 個在等你」的摘要，把使用者手上唯一能立刻做的事收走了，於是他還是得打開面板 —— 那就等於什麼都沒通知。
  8. 一個動作，會把目標寫進標籤。≥2 時主按鈕是「跳過去 · usage」，目標是等最久的那一個（先進先出）。其他 session 的名字是同一個動作換目標，做成安靜的 chip，不是第二種動作。
  9. 有框的一律可以點，沒框的一律是標籤。「在問你問題」是純色塊沒有框，「跳過去」有框或填滿 —— 兩個都是琥珀、都在同一行時，靠這條規則分開，不靠猜。
  10. 「稍後」是有字的按鈕，25pt 高。⏎ / ⎋ 兩個鍵盤提示直接印在按鈕上，手不用離開鍵盤。
  11. 12 秒後自己淡出，狀態留在選單列圖示上。窗口是打擾，圖示是狀態 —— 一個永遠不走的打擾會在三天內被忽略。設計文件的「5 分鐘後恰好再推一次」由圖示與第二次浮窗負責。

刻意拒絕

  • app 名稱 / wordmark。「QuotaMonster」六個字在一秒的閱讀裡是純成本 —— 使用者要的不是知道誰在說話，是知道要做什麼。代價見下方。
  • 角落的 ✕。10–12pt 的命中區要用找的，而「找」正是這個窗口不能發生的事。
  • 任何額度資訊。進度條、百分比、重置時間全部不放。這個窗口與額度無關，放了就等於把藍/綠/紅帶進一個琥珀專屬的地方。
  • 五列堆疊。設計文件明寫 ≥3 同類事件合成一則。五列會讓窗口高過 300pt，變成一個沒有捲軸的小面板。
  • 第二個面板。沒有額度、沒有 agent 樹、沒有 session 清單。要那些的人會去點選單列。
  • emoji。圖示全部是 inline SVG，對應 SF Symbols 的筆重（1.5pt stroke、round cap）。
  • 滑入 / 彈跳動畫。唯一的動作是三個 chevron 的呼吸，與選單列圖示同步（2.1s）。prefers-reduced-motion 下停住。
  • 淺色優先。淺色只附一份、只附 (a)，用來驗琥珀在白底上的明度，不是用來做判斷的那一版。
  • 把等待類別當標題。「在問你問題」是分類，不是內容。它該是 10pt 的 chip，不是 19pt 的標題 —— 那正是「先解碼一則通知」的形狀。
這個方向的代價，誠實記一筆：把 app 身分拿掉之後，第一次看到這個窗口的人仍然需要一次學習 —— 他得把「尖角指著的那顆圖示」跟這個窗口連起來。第二次以後就免費了，第一次不是。 如果實測發現第一次的猶豫太貴，最小的補救是在「稍後」左邊加一行 8.5pt / 24% 的 QUOTAMONSTER： 它在第一次的閱讀裡低於門檻，但在「這是什麼？」的那一眼裡找得到。不要把它加回第一行。
