T1 提示視窗 · 四個方向並排

一個 Claude Code session 卡住、在等人回話的時候，選單列下面應該掉出什麼東西。 四張 mockup 都在下面以真實尺寸嵌入（1 CSS px = 1 pt，預設不縮放）， 排列順序照視窗高度由小到大——38pt、72pt、123pt、142pt——因為「佔多少畫面」正是這四個方向真正的分歧。 它們不是四種樣式，是四種對「打斷」的態度。

看的時候問自己這三題

  1. 問題 01 · 一秒 餘光瞄一眼，一秒內讀完了嗎？

    別正眼盯著看。把視線放到畫面別的地方，用餘光掃過去， 看一秒內有沒有同時拿到哪個專案、在等什麼、等了多久這三件事。 如果需要先對焦、再讀、再想一次「這在講什麼」，那就不是一秒，是三秒——而三秒的東西不配打斷人。

  2. 問題 02 · 代價 它配得上這次打斷、而且會讓開嗎？

    它闖進來的那一刻，有沒有把唯一那個動作（跳過去）直接放到手邊、 關掉它也不用找？然後——它會不會走？ 一個賴著不走、愈長愈高、開始長出第二顆按鈕的東西，已經變成第二個面板了， 而面板使用者本來就打得開，不需要它自己跳出來。

  3. 問題 03 · 誠實 ≥3 合併成一則之後，它還誠實嗎？

    設計文件要求同類事件 ≥3 就合併成一則，所以這一格是四個方向最容易說謊的地方。 看它有沒有假裝自己知道它其實不知道的事：總共幾個、等最久的是誰、 按下去會被帶到哪一個、被折起來的還有幾個——有沒有全部講明白， 還是含糊成一句「有幾個在等你」然後把人丟回面板（那等於沒通知）。

不變的前提（違反就不用看了）： · 琥珀只屬於「等你」，quota 的藍→綠→紅不該出現在這裡 · 深色才算數，淺色只是附錄 · 一個動作「跳過去」＋ 一個不用找的關閉 · 專案名／等什麼／等多久，三件都要在 · 繁體中文，SF Symbols 以內嵌 SVG 近似，不用 emoji

01

Toast橫幅

單獨開啟 →
1 個 380 × 38 pt 2 個 380 × 38 pt ×2（間距 7，共 83） ≥3 380 × 56 pt

位置：選單列下方 6pt，右緣對齊狀態項目右緣（距螢幕右緣 194.7pt），不是對齊螢幕邊——那裡是系統通知的地盤。

賭最小的佔地面積加最熟悉的形狀：寬度就是下拉面板的 380pt， 所以同一個 session 在橫幅和面板裡落在同一欄；起首那顆標記是選單列圖示 1:1； 整個視窗唯一的填色面積就是「跳過去」。

誠實的弱點

1512pt 寬的螢幕上，一個 38pt 高的東西就是很小。使用者的眼睛如果在左下角， 這條橫幅可能整整 8 秒都待在餘光之外——它是靠選單列圖示、提示音、橫幅三件事同時響才成立的。 單獨評分，它是這四個裡面存在感最低的，而那正是「最小佔地面積」這個賭注要付的錢，換個顏色救不回來。

第二個、比較小的代價：合併時按鈕標籤變長（「跳到等最久的」）、時間字串也變長（12m 04s）， 證據行塞得下的名字就變少——6 個在等的時候只點得出兩個。

02

Edge貼邊

單獨開啟 →
1 個 300 × 72 pt 2 個 300 × 102 pt ≥3 300 × 92 pt（比兩個還矮） 寬度恆為 300 pt

位置：上緣與選單列下緣齊平，上方直角、下方 11pt 圓角，無箭頭、無間隙。寬度固定，只有高度會動。

它不是選單列旁邊的 popover，是從選單列拉下來的一格抽屜。 歸屬感靠三件事綁回去：同一個琥珀 #FF9E0A、視窗左上那顆就是選單列圖示（連分段數都跟著等待數走）、 以及頂條上一段 22pt 寬的加厚，正好壓在狀態項目正下方。

誠實的弱點

那個 x 座標不是我們的，而這個方向把全部身家壓在它上面。多裝一個選單列 app，整排就往左位移； 開 Bartender 或 Ice、或瀏海把列塞滿，那顆圖示根本不在畫面上——繫繩指向空氣， Edge 退化成「黏在螢幕頂端的一塊板子」，比單純的 toast 還糟。（檔案裡有誠實畫出這個退化版本，沒有假裝。）

其次：全螢幕 app 會把整條選單列藏起來，錨點可以根本不存在，而這一版沒有回答那時候怎麼辦。 第三：因為齊平、沒有邊框，它很容易被當成某個 app 的下拉選單；琥珀是唯一的分辨線索，沒有第二道防線。

順帶一個不管選哪個方向都值得留著的發現：右緣夾制在 Mac 上其實從來不會觸發—— 系統項目永遠佔住最右邊約 180pt，300pt 的視窗對齊任何構得到的狀態項目 x 都還在畫面內。 那段 clamp 是保險，不是常態路徑；真正的變動全部是往左的。

Question問句

誠實的弱點

把 app 的身分拿掉，代價是第一次。第二次以後免費，第一次不是： 在不熟或共用的機器上，一個沒有署名的琥珀視窗問你「可以執行 rm -rf .build 嗎？」還配一顆顯眼的按鈕， 正好是使用者被訓練成要懷疑的形狀。檔案裡給的最便宜解法是在「稍後」左邊放 8.5pt／24% 的 QUOTAMONSTER ——低於第一眼的門檻，但「這是什麼？」那一瞥找得到。它不能回到第一行。

另外兩個比較小的：兩個在等時 187pt 是單人的一倍半，而 15.5pt 的第二個問句離 19pt 主行夠近， 順序其實是靠位置和填色按鈕撐的，不是靠字級；還有主行是單行尾部截斷， 真正長的問句會變成刪節號，而 mockup 只示範了短句和中句，沒有證明截斷之後還讀得通。

誠實的弱點

一致性是賭注，也是破綻。半徑、節奏、字級都一樣，兩個表面共用同一個輪廓， 分野只剩顏色（整片琥珀底）、寬度（窄 80pt）和那個不存在的箭頭—— 而這三件在淺色模式下全部最弱：琥珀得壓暗成 #E08A00， 與淺色面板之間的亮度差比深色時小得多。

兩個人在等的時候它長到 201pt、兩顆按鈕，開始像一個小面板而不是一則訊息； 如果「兩個同時」才是常態，這個方向的重心就放錯了。 它也繼承了 NSPanel 的天花板：沒有通知中心歷史、鎖定畫面上不存在——人不在螢幕前就等於沒發生過 （這也是設計文件要它搭一發 osascript 通知的原因）。

最後：琥珀底色壓低了內層中性卡的對比，次要讀數（像 ctx）根本放不進來； 而為了讓權限 chip 不被截斷，它得縮成 Bash · git push， 掉了 --force——那恐怕正是整句話裡最該讓人警覺的部分。
