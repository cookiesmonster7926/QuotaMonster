完成訊號 · 方向 QUIET PANEL：只在面板裡，不打斷

「session 工作完成了」是好消息。這個方向的賭注只有一句：好消息不該打斷你，它只需要在你自己去看的時候在那裡。
完成永遠不浮窗、永遠不出聲、永遠不進通知中心。它只改變下拉面板裡那一列的樣子 —— 一個 「剛完成 · 跑了 12m 04s」的狀態，隨時間衰減掉。
量到的數字支持這個取捨：61% 的完成發生在兩分鐘之內，那時你幾乎一定還盯著它。 對著已經在看的人喊，正是把眼睛訓練成無視琥珀色的那件事。
本頁所有面板、列、圖示皆為 1 : 1 實際尺寸（1 CSS px = 1 pt）。

面板標記 ≈ 5.4 次／天（G1 見證 × G3 ≥180s × G2 90s 沉澱 × G4 真結尾） 選單列出聲 ≈ 1.6 次／天（再過 G5 在場 × G6 不在看） 浮窗 0 音效 0 面板高度增加 0 pt 新的重複性計時器 0

1 · 它在螢幕上長這樣

你在別的地方忙了十幾分鐘。usage 那個 session 剛把活做完。 螢幕上什麼都沒有跳出來。你在某個時刻為了看額度按了選單列圖示 —— 它就在最上面那一列。 判斷標準只有一個：面板打開的第一秒，你知不知道哪一個跑完了、跑了多久。

3 · 衰減 —— 「剛完成」不能永遠是「剛」

一個永遠不褪的「剛完成」標記，三小時後就是一句謊話。所以有兩個鐘，而且它們刻意不同步：
鮮度照牆上的鐘走 —— 上緣那條線在 10 分鐘內排空，用字從「剛完成」變成「N 分前完成」。 未讀則等你 —— 勾會一直在，直到你打開過面板（或那個 session 又開始工作）。
這就是這個方向對「使用者可能好幾個小時都不知道它跑完了」的正面回答： 形容詞會老實變舊，標記不會在你看到之前先消失。
全部是 now − finishedAt 的純函式，面板開著的時候才算 —— 沒有新增任何重複性計時器。

5 · 選單列圖示能不能承載「有東西完成了」

這是這個方向唯一真正的風險：完成只在面板裡，那可能好幾個小時都沒被看到。 限制條件很硬 —— 幾何凍結（不能加新形狀）、琥珀保留、額度色階佔掉藍綠紅、 status item 是固定 22pt 寬（StatusItemController 裡有一條寫死的警語：可變寬度會推動選單列上所有鄰居，所以連一個數字都放不下）。
剩下沒有被佔用的維度只有一個：不透明度。答案因此是兩件事，一件會動一次，一件會留著。

「生物出列」的理由：生物是這顆圖示裡唯一永遠不染色的東西 （GlyphRenderer 裡有一條寫死的警語：染色會讓弧與生物糊成一團）， 所以它是唯一不會被額度色階吃掉的載體。而它剛好也是「你的工作」的化身 —— 工作做完了，你看到的就是牠。
總墨量幾乎沒變（周邊 −28%，中心不動），所以這不是一閃、也不會被讀成「壞掉了」或「過期了」 （過期是整顆 ×0.45，比這深得多）。圖地關係換了邊而已。
清除條件：面板被打開，或那個 session 又開始工作，或滿 24 小時。 另外還有一個零像素的通道 —— tooltip（item.button?.toolTip 已經存在）會多一行 「usage · 12m 04s · 58 分前完成」，滑過去就看得到，而且它可以留一整天。

7 · 選了什麼 · 刻意拒絕了什麼 · 誠實的弱點

Chosen

選了什麼

  1. 完成永遠不浮窗、不出聲、不進通知中心。唯一不請自來的東西是選單列那一次 2.4 秒的慢呼吸，而且它照樣走 G5（你在不在）與 G6（你是不是正看著那個 app）—— 算下來一天約 1.6 次。面板裡的標記不受這兩道閘限制，一天約 5.4 次。
  2. 零高度成本。完成狀態整個塞進既有的 header 那一行，外加一條坐在卡片上緣的 1.5pt 線。 使用者拒絕過的那張額外的卡片沒有以任何形式回來。
  3. 形狀承載語意，不是顏色。勾（完成）／ 三個 chevron（等你）。 這是這個 repo 已經寫下的規則：「警示狀態不是靠顏色跟這裡區分的 —— 它是完全不同的形狀」。
  4. 完成綠不是新顏色 —— 就是面板裡 agent pip 與 workflow pip 已經在用的那個綠。 新加的只有形狀與衰減。琥珀一個像素都沒被碰到。
  5. 兩個鐘。鮮度照牆上的鐘衰減（剛完成 → N 分前 → 10 分鐘後全清）， 未讀等你（開過面板才清）。形容詞老實變舊，標記不會在你看到之前先消失。
  6. 「跑了 12m 04s」是主角，不是「完成了」。你已經從勾知道它完成了； 你不知道的是它替你跑了多久 —— 那個數字才決定你要不要現在過去。
  7. 完成的列暫時排到清單最上面（釘住的阻塞卡下方），否則第四個 session 出現時消息就在捲軸外。
  8. 選單列：生物出列。未讀期間兩條弧、兩條暗軌、agent 軌一律 ×0.72，生物維持滿墨。 不是新形狀、不是新顏色，只有不透明度 —— 幾何凍結的承諾沒有被違反。
  9. T2 不再自己發聲，掛成完成的明細行（review 5/5）。 同一件事說兩次是這個設計唯一能被繞過的破口，順手補掉。
  10. 靜音壓下選單列那一下與未讀標記，但不動面板那一列。 面板是你主動去開的；對主動來看的人藏東西不叫「不打擾」。
  11. 零新計時器。衰減是 now − finishedAt 的純函式，面板開著時才算； 圖示本來就每 3 秒重畫一次。這個 app「不在動畫的那幾秒之外不留重複性計時器」的規矩沒有破。

Rejected

刻意拒絕了什麼

  1. 浮窗。一個 NSPanel 從你正在做的事情上拿走一塊螢幕。那個代價只有「有東西被你擋住」付得起。
  2. 音效（包括一個比較輕的音效）。聲音沒有周邊視覺，它是全有全無的。 61% 的完成發生在兩分鐘內，那是對著正在看的人出聲。
  3. osascript 備援。它會以「指令碼編輯器」的身分留在通知中心裡不會走。 好消息的持久歷史就是垃圾。
  4. 任何深淺的琥珀。包含「淡一點的琥珀」「琥珀色的細線」。稀釋琥珀＝毀掉 T1。
  5. 面板加一張「最近完成」卡。使用者已經為了保住高度拒絕過一張額外的卡，那個答案在這裡同樣成立。
  6. 選單列上加一個點／徽章／角標。幾何凍結。 （算過了：底部開口右肩只剩 2.0pt 弧長，放一顆 1.5pt 的點只餘 0.25pt 淨空 —— 1x 下連一個像素都不到。）
  7. 圖示變綠。額度剩 20–50% 時圖示本來就是綠的，完成訊號會直接消失在裡面。
  8. 呼吸／脈動／任何重複的動作。重複的動作 = T1 的專屬語彙。完成只動一次，而且是慢的。
  9. 永不消失的完成標記。三小時後還寫著「剛完成」是一句謊話，而說謊的 UI 會被整個忽略。
  10. 「最近完成」的歷史清單。會越長越長，而且沒有人回頭看。要歷史去看 transcript。
  11. 把 N 個完成合併成「2 個 session 完成」。那是通知的做法。面板裡你已經在看了，兩列比一句話說得多且不多佔高度。

Weakness

這個方向誠實的弱點

  1. 最大的弱點：它可能根本沒被看到。整個方向壓在一個沒有被測量過的假設上 —— 「你本來就會為了看額度打開面板」。如果你一天只開兩次面板， 那一天 5.4 次的完成標記裡有一大半會在你看到之前就過了鮮度。 這個假設必須先量（面板開啟頻率），再決定要不要加強主動通道。
  2. 「生物出列」在淺色選單列的 1x 螢幕上接近讀不出來。 黑墨的暗軌只有 0.24–0.32，×0.72 的差不到一階。這是「幾何凍結 + 琥珀保留 + 藍綠紅被額度佔走」 三個約束的算術結果，不是品味問題 —— 剩下的維度真的只有不透明度。
  3. 兩個鐘要解釋。第一次看到一個灰色的勾配上「58 分前完成」的人， 不會知道那個勾為什麼還在、為什麼是灰的。這是這個設計唯一需要被教一次的地方。
  4. 面板裡其實有三個綠，而且其中一個就在同一張卡裡。完成綠是 #30D158，而 SessionRow.contextColour 在 ctx < 70% 時回傳的 .green 是同一個色值 —— 也就是說完成的那一列，會排空的綠線正上方就有一條綠色的 ctx 條。（第三個是 workflow pip 的完成綠，還有額度綠代表「剩 20–50%」。）目前只靠粗細（1.5pt / 3pt）、位置（卡片邊 / 內文行）與形狀（勾 / 方 pip / 圓點）分開。對紅綠色弱的使用者，只剩形狀。
    真正的修法有兩條，都要使用者拍板：把 ctx 條改成單色（它本來就不需要顏色，數字已經在旁邊），或者完成改用別的載體。這一頁把撞色照實畫出來，沒有調淡。
  5. 「跑了 12m 04s」量的是無人看管的時間，不是回合長度。 waiting → busy → idle 會讓一個實際跑了 20 分鐘的回合顯示 30s。 設計上是對的（你回答的那一刻就是你在場的那一刻），但讀起來會像 bug， 而且第一次遇到的人會以為數字壞了。
  6. 排序會跳。面板正開著的時候有 session 完成，它會跳到清單最上面 —— 你正要點的那一列會往下移一格。（緩解：只在面板關著的時候重排。但那又表示 面板開著時完成的那一列可能在捲軸外。兩害，還沒有量哪一個比較痛。）
  7. T2 從「自己會響」降級成「完成的明細行」是一個真正的功能減損。 目前 T2 會出聲，改完之後在「扇出散完但 session 立刻開下一輪」的情況下 只會在 batchAttachWindow（180s）之後才單獨出現一次。 扇出很長的多階段 workflow，感覺上會變安靜。

一句話總結這個方向的立場：它把「會不會漏看」這個風險，換掉了「會不會被吵到」這個風險。 漏看一次完成的代價是「晚幾分鐘回去」；被吵一次的代價是「下次琥珀亮起來時你的眼睛已經學會不看了」。 這個 repo 已經寫下的那條規則 ——「在錯的時間響的通知，比沒有通知更糟」—— 選的是同一邊。
