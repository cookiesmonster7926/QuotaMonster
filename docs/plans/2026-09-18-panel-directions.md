## Stats 忠實派 — Stats-Faithful（95/120）

**主張：** Borrow the Stats popover wholesale — dark rounded panel, header with centred title, lifted cards each holding colour-keyed readouts + a real chart + a progress bar + a footline, uppercase letterspaced labels between blocks — and spend the entire design budget on the one thing Stats never had to solve: turning TOP PROCESSES into a three-level agent tree that still fits in 380pt.

**樹怎麼解的：** Three levels get three different row *types* instead of three indents, so depth is carried by form rather than by whitespace. (1) Session = a full-width 32pt table row: status dot, id, mono path, status pill, elapsed, and a 20pt context micro-bar with its %. (2) Workflow = a single 24pt row hung off a 1px rail, whose right end is a 7-segment pip meter (3 green done / 4 blue running) plus "3/7" — so the fan-out has a *shape* before you read a single agent name. (3) Agents = a recessed inset tray holding a 2-column chip grid; the shared `design:` namespace is hoisted into the tray's micro-header (`design:*` … `3 done · 4 running`) so each chip carries only the leaf name and a tabular duration. Completed agents then collapse into one full-width dashed summary row ("3 已完成 · 最後 state-machine-kinetic 5:02"), which hands the grid to the 4 agents that are actually burning quota right now. A 7-agent fan-out therefore costs 4 rows and ~106pt, not 7 indented lines, and total indentation is one 24pt rail — nothing marches rightwards as the tree deepens. The whole tree lives in one card so it reads as the structured equivalent of the Stats process table.

**阻塞怎麼處理的：** One amber, reserved for exactly one meaning. Context-fill bars are deliberately neutral grey even at 61%, so amber never has to compete with itself. Four quiet, coordinated cues: (1) a dedicated ACTION REQUIRED card pinned above QUOTA — the first thing under the header — with a 3pt amber rail, the session id, the literal prompt in mono on a recessed strip (`Bash · git push --force`), the 2m elapsed, and a 前往 session button, so the urgent item is also the actionable one; (2) in the tree, the whole f1-e3 group (session row plus its running agent) gets an amber wash and a 2.5pt left rail, so it reads as one blocked unit rather than a highlighted line; (3) its pill is solid-filled amber where every other session's pill is tinted — a fill/tint jump, not a colour shout, and the only solid fill in the panel; (4) its status dot carries a slow 1.9s halo pulse. Nothing is red, nothing blinks fast, nothing is bigger than its neighbours. Outside the panel, the menu-bar item permanently reserves a 5pt slot at its leading edge that only lights amber (with a 1.7s blink) while a session is blocked, and the numerals go amber with it — visible without opening anything, and the item never changes width.

**選單列圖示：** All three keep the fixed-width discipline and share one blocked language, so the choice never changes how urgency is communicated. A (50pt, ring gauge + "28%") splits the job: the arc carries trend peripherally, the numeral carries precision — the closest thing to Stats' own vocabulary and the only one that still reads at arm's length. B (62pt, mark + stacked 5H/7D) is faithful to Stats' network module's two-line up/down readout and is the only variant showing both windows at once, but it pays for that with 8.5pt digits that squint on a non-Retina external display. C (58pt, five 30-minute burn bars with a baseline + "28%") is the only one that shows the fan-out spike — the last bar is the 5-agent surge — but a micro bar chart with no motion is the weakest static read of the three. Ship A. The principle the user stated is that the icon is simple and the panel holds the detail; A is the one you can read without deciding to read it, and everything B and C add is one click away.

**評審必修項：**
- (macOS 原生度) Cap the panel around 620pt and make the sessions card a scroll region with the header, ACTION REQUIRED card and quota pinned above it — at 856pt the design is out of headroom with FOUR sessions, and the user's own stated workload is ten subagents at a time.
- (視覺品質) Get it under ~620pt now, not later: cap the sessions card, scroll it under a pinned section label, and delete the duplicate '3 分鐘前' freshness string. 856pt is not headroom-limited, it already overflows a 13" screen with a Dock.
- (資訊設計) Delete the mirrored sparkline and draw one burn line on a real baseline at full card width; then flatten the agent tray so the tree is not a box inside a box inside a box.

**設計者自陳缺點：**
- The popover renders 856pt tall (measured, not estimated). On a 13" MacBook only ~865pt exist below the menu bar, so it fits today but has no headroom: with a second fan-out or a fifth session the sessions card has to become a scroll region, and I have not designed that scroll affordance.
- Every project here happens to hold exactly one session, so the project grouping is doing no visible work — the design currently leans on the session row carrying its own path. Two sessions in one project would need a real project header row that this mockup does not specify.
- The 5-hour mirrored chart puts two different units on one mirrored axis: cumulative % used above the baseline, instantaneous %/h below. It is legible here only because each readout row's colour keys to its area, and a purist would rightly argue the two halves are not comparable.
- Agent chip names ellipse past ~16 characters. I bought the room by hoisting the shared `design:` prefix into the tray header, which only works when a fan-out actually shares a namespace — a mixed-namespace fan-out loses that and truncates harder.
- The 7-day chart's Fable segments are 1.8px tall because Fable really is 1%. Truthful, but the chart cannot carry that value; the purple readout row is doing the work, and the stacked segment is close to decoration.
- Variant B's 8.5pt stacked digits are below what I would normally ship into a menu bar, and the 5pt reserved amber slot costs 8pt of width in every variant even when nothing is blocked.
- Static single state: no hover, press, focus or empty states, no truncation behaviour for very long project paths, and the 'freshness: 3 minutes ago' string is shown twice (label right + footer) which is one repetition more than the panel needs.

## 密集儀表派 — 密度儀表 · Dense Instrument（89/120）

**主張：** A Braun-style instrument face where every pixel is a labelled measurement — small multiples instead of one hero chart, hairline-ruled columns, tabular figures everywhere — so the agent tree reads as a dense ledger with structure rather than a wall of indented text.

**樹怎麼解的：** Four logical levels (project → session → workflow phase → agent) are compressed into two visual indents. The project never gets its own row: it rides on the session row as a dimmed mono path (`usage-97  ~/Antigravity/usage`), so the hierarchy starts one level shallower than it really is. Everything below a session hangs off ONE 20pt rail with a 1pt hairline and 7pt connector ticks — the workflow row and its agents share that single indent, distinguished by weight and glyph rather than by another 16pt of whitespace. The 7-agent fan-out is then solved twice at two resolutions: the workflow row carries a 68pt strip of seven 8×10 cells (3 solid green = done, 4 blue-outlined = running) plus `3/7`, so the whole phase is legible without reading a single agent name; underneath, the agents listed individually become a 21pt-per-row ledger whose right edge is a proper horizontal bar chart of elapsed time on a shared 5m02s scale — five bars, common baseline, so you can see at a glance that creature-motif is lagging and state-machine-kinetic ran longest. Only 5 of 7 are listed; the tail collapses to one 19pt grey line. Total cost for a 7-agent fan-out: 23 + 5×21 + 19 = 147pt, inside 352pt of content width, with no name truncated.

**阻塞怎麼處理的：** No duplicate alert banner — the blocked session IS the alert, fused into one card and hoisted to the top of the list. It is the only tinted block in an otherwise achromatic panel: a 2pt amber inset left bar, an 11% amber wash, a 0.5pt amber hairline ring, and a 7pt amber dot with a 2.5pt halo breathing on a 2.2s cycle. Inside the card the reason is quoted verbatim in a recessed mono chip — `PERMISSION · Bash git push --force` — with a live `⌘ ⇧ A` keycap, so the panel answers "what does it want?" without a second click. It is reinforced, not repeated, in two other places: the header roll-up's third cell is an amber pill reading **1 / BLOCKED** (the only coloured thing above the fold), and in the menu bar the quota glyph is replaced outright by an amber alert ring so blocked outranks quota before the panel is even open. Three touchpoints, one colour, zero flashing.

**選單列圖示：** All three keep a fixed width so neighbours never jump, all sit inside the 22pt content box, and all share one blocked language: the glyph is replaced by an amber alert mark and the numerals turn amber — the width is identical in both states, so nothing shifts when a session starts waiting. **A · 錶面 + 百分比 (54pt)** is a 15pt ring gauge at 28% plus the tabular numeral: two channels, one glance — the arc answers "how full" pre-attentively, the number answers "exactly how full". **B · 雙行讀數 (52pt)** is Stats' up/down idiom applied to the two windows, 5H 28% over 7D 18% at 8.5pt mono — more information, and legible on Retina, but it asks you to read rather than glance. **C · 柱狀 + 百分比 (56pt)** pairs the number with a real 6-bar histogram of the last 90 minutes in 15-minute buckets (0.9, 0.9, 1.2, 2.4, 4.0, 8.0 %) on a baseline — the ramp itself is the burn warning, which is the one thing this app knows that a plain percentage doesn't. **I would ship A.** The brief is "simple and easy to read", and A is the only one that needs no reading at all to be useful: the ring tells you the state at 22pt from the corner of your eye, the numeral is there when you want precision, and it leaves the burn story — which is genuinely a chart, not a glyph — to the panel where it has 352pt to be honest in. C is the power-user alternative if the user finds himself opening the panel just to check the burn.

**評審必修項：**
- (macOS 原生度) Spend amber once. Make the burn hatch and the projected-overrun zone neutral graphite with a labelled pace tick, so the only amber pixels in the panel belong to the blocked session — and raise every sub-9.5pt label to 10pt while you are in there.
- (視覺品質) Set a 10px floor on every label and re-space to it. A density thesis that only works below AppKit's minimum legible size is not dense, it is small.
- (資訊設計) Give amber one owner: cool the burn band to neutral+small amber marker so the blocked card is the only amber block, and unclip the 100% ceiling label that the band's top edge is currently cutting.

**設計者自陳缺點：**
- The panel stands about 585pt tall with this data. One more busy session, or a second expanded workflow, pushes it past a comfortable popover and it needs scrolling or per-session collapse — neither of which this mockup designs.
- The density is tuned to SF Pro and SF Mono metrics. On the Segoe / IBM Plex fallback the 7.5–10pt labels (CTX, PHASE, PERMISSION, SESSIONS) and the tight right-hand column of state + elapsed + context will crowd, and the session row has only ~20pt of slack before the path starts eliding.
- Amber does three jobs at once here — blocked session, burn warning, projected-overrun hatch on the 5H bar — so the panel currently has two amber zones and the eye has to decide which one is the emergency. It holds because they are vertically separated, but a third amber event would break it.
- The 7-cell fan strip encodes only done/running. A failed or queued agent needs a third and fourth treatment, and the strip runs out of room somewhere around 12 cells; a 20-subagent fan-out would need a different mark entirely.
- Truncating to 5 of 7 agents with '另有 2 個 agent 已完成' is a rule I asserted rather than designed — what gets dropped, and how you expand it, is unspecified.
- Everything except the ⌘⇧A keycap is read-only. An instrument face this dense invites clicking rows to drill in, and no hover, press or focus state is defined for the 30pt session rows or the 21pt agent rows.

## Orbit 半透明派 — Orbit — 半透明控制面板（89/120）

**主張：** 面板用 macOS 原生的「圓形 icon well + 右側控制 + hairline 分隔」列式語彙承載所有資訊，材質真的疊在桌布上做事；階層不靠縮排，而是靠容器嵌套、面板邊緣的狀態色帶，以及把 1:1 的層級直接壓成同一列。

**樹怎麼解的：** 四層（project → session → workflow → agent）在 380pt 內只花了三個縮排位置，最深的元素離左緣 68pt，還剩 312pt 給內容：(1) project 與 session 在這份資料裡是 1:1，所以壓成同一列——session 名稱 12.5pt semibold 在上、路徑 10pt mono 在下，不再各佔一列；只有真的會分叉的層級才配得上垂直空間。(2) 狀態不佔寬度：每個 session 列在面板最左緣有一條 2.5pt 的色帶（blue 執行中／amber 等你／灰 閒置），是一條貼邊的 gutter，成本 0pt。(3) workflow 不是「再縮排一次的文字」，而是一張內縮 51pt 的圓角卡片（背景 white .055 + 0.5px inset stroke），縮排由容器表達，卡片頭是階段名 + 右側 mono 的 wf id。(4) agent 只在卡片內縮 13pt，用真正的樹幹：一條 1px 垂直 spine 加每列 6px 的橫向 tick，且 session well 底部有一條 L 形圓角 connector 接進卡片，所以「誰是誰的小孩」是畫出來的而不是靠對齊猜的。(5) 名稱用 11pt mono，namespace 前綴（design:）降到 t3、實際名稱維持 t1，掃視時只讀得到差異的那段。(6) 7 個 agent 的 fan-out 在總覽頁壓成一條 7 顆 pip 的進度計（實心＝完成、空心環＝執行中）＋「3/7 完成 · 4 執行中」＋一行截斷的名稱串；Agents 分頁才展開全名，並把 3 個完成中沒列出的收成「另有 2 個已完成的 agent」。(7) 沒有子代理的 session 不留空卡片，改集中到分頁下半的「其他工作階段 · 無執行中的 agent」。

**阻塞怎麼處理的：** f1-e3 被提升成一條橫貫整個面板寬度的 banner，位置在標題列與 tab bar 之間——也就是在分頁系統之外，所以不管你在總覽、Agents 還是歷史分頁，它都在原地不會被切走。視覺上用四件事疊出無法忽略、但不刺眼的強度：面板裡唯一的琥珀色底（amber .135 / 淺色 .20）、貼左緣的 2pt inset 琥珀色軌、填滿的琥珀 icon well（對話泡泡＋三個點＝「在等你回話」，不是驚嘆號那種錯誤語氣），以及 well 外一圈 2.8s 緩慢擴散的 ping ring（prefers-reduced-motion 會停成靜態環）。內容直接給可行動的三件事：session 名、等了多久、以及那道 mono code chip 寫著的實際指令 `Bash git push --force`，右邊一顆「開啟 ↗」膠囊鈕。同一把琥珀色在下方的 session 列邊帶與狀態 chip 再出現一次，所以視線從 banner 掉到清單時能接得上；而在你還沒點開面板之前，選單列圖示上那顆琥珀徽章已經先講了同一件事。

**選單列圖示：** 三個變體刻意走三種不同的路子，而不是同一個東西的三種粗細：A 是 icon-led（15pt 環形進度＋28%），B 是 data-led（小環＋5h/7d 兩層 9.5pt tabular 數字，給同時盯兩個視窗的人），C 是 type-led（只有 28% 加一條 26pt 底線量表，選單列擠爆時的最小佔位）。三者都是固定寬度（50 / 56 / 42pt，遠低於 100pt），數字用 tabular figures 所以 28% → 29% 不會讓鄰居抖動。圖形一律 currentColor，等同 macOS 的 template image，淺色列、深色列、任何桌布上都自動翻色。唯一的非 template 元素是共用的 10pt 琥珀徽章（深色驚嘆號在琥珀圓上，形狀＋顏色雙通道，不只靠顏色），它在三個變體裡都是絕對定位或預留固定 slot，出現時寬度完全不變；A 與 B 在 blocked 時會把 mark 壓到 25% 不透明度讓徽章接手，C 則預留左側 10pt 徽章欄。我會出 A：環形本身就是「還剩多少」的直覺語言，配數字後不需要學，而且 50pt 是三者中資訊密度與佔位的最佳交換。

**評審必修項：**
- (macOS 原生度) Put the full agent tree on Overview. Kill the icon wells (or shrink them to 14pt dots) to buy back the width, and demote the tabs to a filter or drop them — the centrepiece cannot be one click away.
- (視覺品質) Put the named running agents back on the Overview — the tree is the product, and no tab may be able to hide it. If the tab bar survives, Overview must carry the full fan-out and Agents becomes history/detail.
- (資訊設計) Raise material opacity and desaturate so the wallpaper stops tinting the UI (the amber banner must not go olive), and bring the real tree onto Overview — the hierarchy is the product, not a tab.

**設計者自陳缺點：**
- 琥珀色做了兩份工：blocked banner 與 burn 警告（「47m 後用完」）共用同一個色相。語意上都是「需要你注意」所以說得通，但同時出現時會稍微分掉 banner 的獨佔性；如果之後要加第三種警示，這套色彩預算就不夠了。
- 分頁是有代價的：agent 全名藏在 Agents 分頁後面，總覽只給 pip 進度計＋三個截斷的名稱。常駐在總覽的人不會看到完整樹狀。我認為這個交換是對的（blocked 已被提到分頁之外），但它確實是個取捨。
- 面板約 605pt 高，已經接近舒適上限。這份 mockup 沒有設計捲動狀態：真的有 10 個 session 時，sticky section label、捲動陰影、以及「捲到哪裡了」的處理都還沒解。
- 9.5pt 的狀態 chip 與 10pt 的次要文字在 Retina 上很好，但在 1x 外接螢幕上偏臨界。這是 Stats 的密度慣例，不是錯誤，但值得在真機上再驗一次。
- backdrop-filter 只是 NSVisualEffectView 的近似。真正的 .hudWindow / .popover 材質會隨桌布做不同的 tint 與 luminance 映射，淺色材質實作出來很可能比這裡更奶白、對比更低。
- 5 小時量表上那段斜紋投影區（28% → 100%）第一次看需要靠右下那顆琥珀膠囊才讀得懂，本身沒有圖例。第二次之後就會了，但它不是自我解釋的。
- 這棵樹只證明了「一個 phase 下 7 個 agent」這個規模。同一階段 20 個以上 agent 時需要折疊或虛擬捲動，那個狀態沒有設計。

## 留白編輯派 — Calm Ledger（87/120）

**主張：** The panel is read like a page, not a dashboard: one urgent headline, one big number with a burn chart that proves the warning, a two-line ledger, and then the agent tree set as an indented list with a hairline spine — one amber accent, no boxes except the one thing that is actually wrong.

**樹怎麼解的：** Four stacked cues instead of indentation alone, so depth survives at 380pt. (1) Indent is cheap: 22pt for level 2, 17pt more for level 3 — 39pt total, leaving 289pt of usable row, and each level carries a 1px hairline spine (session-level at --rule, agent-level at --fg4/45%) that runs only as far as its last child, so the eye tracks the group without ASCII box-drawing. (2) The type ramp drops at every level: session 12.5px/600 at full contrast, workflow 11.5px/500 at 62%, agents 11.5px/regular at 62% with 10.5px tabular times at 42%. (3) A fixed status gutter at each level — 14pt for sessions, 9pt for agents — so all dots form two clean vertical rules rather than ragged glyphs. (4) The 7-way fan-out is summarised before it is listed: the workflow row reads `Design 階段 wf_79e5d247 · 3/7 完成` followed by a 7-cell segmented strip (3 solid = done, 4 faint and slowly pulsing = running) — you get the shape of the fan-out in 3pt of height, then the four running agents are listed by name with elapsed time, one finished one is shown with a check, and the two remaining completions collapse into `＋2 個已完成`. Seven agents therefore cost 6 rows of 21pt, not 7 rows plus a header, and the summary strip stays true even when collapsed.

**阻塞怎麼處理的：** It is stated twice, at two different volumes, and nowhere else. At the top — above the quota, the first thing under the brand line — sits the only filled block in the panel: a 9pt-radius amber-tinted card (13% accent on dark, 10% on light) with a 2pt solid accent edge at its left, a pause-in-a-ring glyph, and three lines that answer the whole question without a click: `f1-e3 正在等你回覆 / 已等 2 分`, the actual ask (`允許執行 Bash` + `git push --force` in a mono chip), and the cost of ignoring it (`~/Antigravity/F1 · 1 個 agent 跟著停住`) with a `⌘1 前往` key pill. Because it is the only tinted, bordered, coloured element in an otherwise rule-free panel, it is unmissable by contrast rather than by loudness — no red, no icon badge, no shouting weight. Then, 300pt lower, the same session in the list carries the only amber dot in the tree (7pt, with a slow 1.9s halo ring) and the only amber state word `等待你`, so the alarm and the row are obviously the same object. Everything else in the panel — dots, times, meters, chart line — is monochrome, which is what buys the amber its force.

**選單列圖示：** All three are fixed-width, numeric, and template-monochrome in the normal state so they behave on a light bar, a dark bar and a wallpaper; they differ in how they signal blocked, which is the only decision that matters. A (56pt, ring gauge + `28%`) signals by recolouring the glyph: the whole ring turns amber and its centre fills, a shape change plus a colour change in the same 15pt, with the number untouched. B (50pt, vertical gauge + `28%`) signals by lighting the item's field — an amber tinted chip with a hairline — which is the strongest peripheral signal of the three but reads like a selected/open menu item, which is a lie about state. C (68pt, 8-bar histogram of the last 8×20min + `28%`) signals with a 6pt amber badge dot in permanently reserved space, so nothing ever shifts; but the histogram is 22pt of chart at 14pt tall, which is decoration the panel already does better, and it is the widest. Ship A: it is the Stats idiom (small glyph, compact readout), the ring doubles as the 5-hour gauge so the icon is useful when nothing is wrong, the blocked state changes hue and interior fill at once so it is caught in peripheral vision, and 56pt is well inside the safe zone. One caveat worth stating: the amber state is deliberately non-template, so it will not tint with the bar — that is the point, but it means the asset must be supplied as a non-template NSImage and checked against `NSColor.controlAccentColor` users who run an amber accent.

**評審必修項：**
- (macOS 原生度) Give the agent level a non-linear container — a two-column chip grid or a collapsed running/done split — so a 12-agent fan-out does not add 250pt of indented text, and replace 'ctx 34%' with a comparable micro-bar.
- (視覺品質) Bring the lede down to ~28px at weight 500–600 tabular and the panel border to 0.5px. The ultralight 34px number is the one element that tells a reviewer this was designed in a browser.
- (資訊設計) The 3-done/4-running segment strip is illegible — give done and running a real tonal (and shape) difference, and raise the 7-day meters off the floor so 18% and 1% are comparable values rather than faint rules.

**設計者自陳缺點：**
- The panel is 855pt tall with this data. On a 1080p display that is most of the screen, and a fifth session or a second expanded workflow would overflow — it needs a max-height around 620pt with the sessions section scrolling under a pinned header, which this mockup does not show.
- The calm reading depends on exactly one thing being wrong. With two blocked sessions the top block either stacks (and pushes the quota below 120pt) or collapses to a count, and neither is designed here.
- Variant B's normal state is nearly invisible: a 3×4pt fill at the bottom of a faint 14pt track is not legible at a glance, so B only really works in its blocked state.
- The burn chart spends 60% of its width near the baseline because usage was flat until 30 minutes ago. It is honest and the emptiness is the message, but a flatter day would make it look like a decorative rule with a dot on it.
- One accent for two different meanings — 'someone is waiting' and 'you will run out' — is economical but conflates urgency types. If burn warnings become frequent they will dilute the amber that the blocked state depends on.
- The tree only renders one workflow level. A workflow nested inside a workflow would need a fourth indent (56pt) and the agent names would start truncating.
- Context percentage is text-only (`ctx 34%`), so you cannot compare the four sessions at a glance the way the ledger meters let you compare quotas.
- Hairlines are authored at 0.5px and browsers round them inconsistently; on a real NSVisualEffectView these would be NSBox separators, so the mockup's rule contrast will need re-tuning against real material vibrancy.

## 時間軸派 — Spine — 時間軸即骨架（85/120）

**主張：** One time axis runs the whole panel: the 5-hour window is a burn curve at the top, a ×20 zoom cone drops out of it into the last 15 minutes, and every session and agent below hangs off the same vertical NOW line as a right-aligned duration bar.

**樹怎麼解的：** Three moves, none of them indentation. (1) I deleted a level: the project is not a row, it is the dim monospace path on line 2 of the session row, so four levels become three. (2) Two indent stops only, 16pt each, drawn as a 1px rail with 8pt elbows rather than whitespace — the rail is two absolutely-positioned divs per group with exact top/height, so it terminates on the last child instead of running to the group's bottom. The full fan-out of 7 never becomes 7 more rows: the phase row carries a 57pt pip meter (3 solid / 4 at 26% purple) that states 3-done-of-7 in one glance, so only the 5 named agents get rows and the 2 unlisted done ones are accounted for without a "+2 more" line. (3) The namespace `design:` is hoisted off all five agents onto the phase row, which buys ~34pt of gutter — that is what lets `state-machine-kinetic` fit at 10px without an ellipsis in the 109pt left after the indent. Geometry: 14 pad + 144 gutter + 6 + 172 track + 6 + 34 duration + 8 pad = 384. The Gantt is not mush because the track is NOT the 5-hour scale — at 5h a 4-minute agent would be 3px. It is a 15-minute lens at 11.5px/min (4m12s = 48pt, 2m55s = 33pt), the lens is drawn as a bracket on the main axis (it really is only 5% of it) and expanded through a literal SVG cone into the track's exact left and right edges, the Instruments overview→detail idiom. Bars are right-aligned to NOW, which gives one hard shared edge instead of a ragged Gantt; −5m and −10m gridlines run down every row so durations compare across the tree; the one bar that overruns the lens (obsidian-4a, 41m) is clipped with a left mask fade and a « chevron; the done agent is a hollow outline ending 40s short of NOW; the phase gets a purple bracket spanning its children, with `wf_79e5d247` floating in the empty past to its left.

**阻塞怎麼處理的：** Six coordinated signals, each individually quiet. A 44pt full-bleed amber band directly under the title with a 3pt amber left edge, a filled amber circle badge (breathing 1→0.46 over 2.6s, disabled under prefers-reduced-motion), "f1-e3 正在等你的許可", the literal reason `Bash git push --force` in mono, "2m" and a disclosure chevron. The third rollup chip turns amber: "1 待你回應". In the tree, f1-e3's whole group carries a 2pt amber inset left edge and a 5% amber wash — the same left edge as the alert strip, which reads as "that banner is this row". Its status dot is amber with a 3pt amber halo, it is the only session with a chip (待你回應), its duration bar is amber 45° hatching instead of a solid fill so the 2 minutes it has been stuck read as blocked-and-growing on the same time spine, its track subline repeats `git push --force` in amber mono, and its duration column reads 2m / WAIT in amber. Restraint comes from the palette: amber, never red — red is reserved for the quota lockout zone, so the two urgencies never compete. Nothing pulses except one 20pt glyph, and the amber fill is 15% in dark / 22% in light, not a saturated block.

**選單列圖示：** All three share one principle so the family is coherent: the leftmost cell is a permanent "status slot" that shows information normally and becomes a SOLID amber fill when blocked. That matters because a coloured glyph or amber text is unreadable on a light menu bar and over a bright wallpaper — a filled shape with dark text on it is legible on literally any background, which is the only treatment that survives the light-bar / dark-bar / arbitrary-wallpaper constraint. Every variant keeps its exact pixel width across both states so neighbours never jump. A — 倒數環, 54×22: a ring showing the 5-hour window 56% elapsed plus "2h12" remaining; one shape and four characters. B — 雙行讀數, 36×22: the Stats two-line idiom, 28% over 2h12 with a 3.4pt vertical meter as the slot; the most compact. C — 微型時間軸, 80×22: "28%" plus a 36pt bar that is the whole 5-hour window — elapsed fill, a triangle at NOW, and a red tail from projected exhaustion to reset, so the burn risk is visible without opening the panel. I would ship A. The brief was "simple and easy to read" and A is the only one that is a single glyph plus a single number; it also answers the question this user actually asks all day ("how long have I got?") rather than a percentage that needs converting. C is the right upgrade for someone who wants the lockout risk permanently on screen, and it is the one that rhymes with the panel. B is there for a crowded menu bar and I would offer it as a preference, not a default.

**評審必修項：**
- (macOS 原生度) Either make the lens auto-fit the longest running item (and animate the cone with it) or delete the Gantt entirely and give those 172pt back to names, status and context — keeping the burn curve at the top, where a time axis actually belongs.
- (視覺品質) Move the shadow off `filter` and onto `box-shadow` on .qm-bodywrap — as authored, the ancestor filter creates a backdrop root and the vibrancy never renders. Then raise the permission string off 9.5px.
- (資訊設計) Demote the red lockout hatch (thin rule + label, not a filled field) so the blocked banner is the loudest thing on screen; right now a chart out-shouts the human who is waiting.

**設計者自陳缺點：**
- The panel is 712pt tall. That is legitimate for a pro tool (Stats' popovers get similar with a long process table) but it is the tallest thing in this comparison, and with 8+ live sessions the Gantt would need a scroll region with a sticky ruler and a pinned NOW line — designed for, but not shown here.
- The 15-minute lens is a fixed choice. It fits everything in this dataset except obsidian-4a (41m), which clips. A session idle for 3 hours, or a genuinely long-running agent, degrades to 'a full-width bar with a chevron' and the Gantt stops discriminating. The real app needs the lens to auto-fit the longest running item (or offer 15m / 1h / 5h), and the cone width must animate with it.
- The burn curve's steep recent segment is doing a lot of work. It is honest for this data — 18% in 12 minutes because five subagents launched — but a projection off a 12-minute window is statistically fragile, and if the panel cries wolf at every subagent fan-out the amber warning line loses its meaning within a week. It needs hysteresis and a confidence band, not a single dashed line.
- Two facts share one chart with different units: x is time, y is quota percent. That is correct but it takes a beat to learn, and 'time elapsed 56% / quota used 28%' is a comparison the chart shows implicitly rather than stating. The 7-day meters solve the same problem more bluntly with a pace tick; the two treatments are not consistent with each other.
- The phase pip meter compresses 7 agents into 3-solid/4-light. It scales to maybe 12 before the pips stop being countable, and it cannot express a failed agent without adding a third colour to a 6pt square.
- Tree rails are hand-placed with absolute top/height values per group. That is fine in a mockup and fragile in production — it wants to be a drawn SVG overlay computed from measured row positions, or the rails will drift the moment a row height changes.
