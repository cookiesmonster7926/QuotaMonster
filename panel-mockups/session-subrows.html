session 子列：怎麼看得出「什麼還沒好」

現在的樣子（最上面那個）：兩隻已經做完的 agent 還掛在列表上，灰點， 跟「還在跑」長得一樣；而真正還沒好的 workflow 反而被收進「另有 N 個已完成」那一行裡。

⚠️ 新前提：一般 agent 的完成狀態**讀得到**（實測 100% 覆蓋， 背景走母 transcript 的 task-notification、前景走 tool_result 的 status）， 狀態有 completed / failed / killed。所以下面三個都建立在「分得出做完沒」之上。

現在（對照組）

修t2 usageBUSY83h
ctx77% 1M
Verify AGENTS counter livegeneral-purpose
Demo subagent for panelgeneral-purpose
另有 8 個 workflow 已完成

兩隻做完的 agent 佔了兩行，而「還沒好的是什麼」看不出來。

A —— 只留還沒好的，其餘全部收合（含 agent）

修t2 usageBUSY83h
ctx77% 1M
WFBuild wf_5a0dae95 2/4
AGVerify AGENTS counter live general-purpose
已完成 8 個 workflow · 2 個 agent · 2 個失敗

有自己一行的＝還沒好。做完的全部進最後那一行。 左邊那個小標籤說得出是 workflow 還是 agent。

B —— 同 A，但用文字標而不是色塊

修t2 usageBUSY83h
ctx77% 1M
workflowBuild wf_5a0dae95 2/4
agentVerify AGENTS counter live general-purpose
已完成 8 個 workflow · 2 個 agent · 2 個失敗

比 A 安靜，但那一欄固定寬度會吃掉描述的空間（描述本來就常被截斷）。

C —— 一行講完，不列細項

修t2 usageBUSY83h
ctx77% 1M
還沒好1 個 workflow（2/4）· 1 個 agent 已完成 10 · 失敗 2

最省高度（一個 session 固定兩行）。代價：看不出哪一個還沒好， 而你原本的抱怨正是「不知道是什麼還沒好」—— 這個選項只解決了一半。

沒有東西在跑時，三個選項長什麼樣

修t2usage IDLE2h
ctx22% 1M
已完成 8 個 workflow · 2 個 agent · 2 個失敗

三個選項在這種情況下一模一樣：只剩收合那一行。 這才是常態 —— 多數時間什麼都沒在跑，而現在的版本在這種時候還是會列出一堆灰點。
